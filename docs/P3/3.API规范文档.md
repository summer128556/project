# P3 API 规范文档

> 项目：Campus Helper 校园互助服务平台  
> 架构：前后端分离 + 分层单体架构  
> 风格：RESTful API  
> 数据格式：JSON  
> 认证方式：JWT Bearer Token

## 1. API 设计目标

本接口文档用于指导前后端在 P4/P5 阶段进行联调。接口覆盖 P0 核心流程：用户登录与认证、任务发布与浏览、接单、订单详情、完成凭证、确认完成、取消订单、评价提交、后台审核。

接口设计遵循以下原则：

1. URL 使用名词复数形式，例如 `/api/tasks`、`/api/orders/{id}`。
2. 使用 HTTP 方法表达动作：`GET` 查询、`POST` 创建、`PUT` 修改。
3. 所有需要登录的接口都要求 `Authorization: Bearer <token>`。
4. 所有响应使用统一结构，便于前端统一处理。
5. 对常见异常明确错误码，避免仅返回笼统失败信息。

## 2. 通用约定

### 2.1 请求头

| Header                           | 是否必填    | 说明       |
|----------------------------------|---------|----------|
| `Content-Type: application/json` | 是       | JSON 请求体 |
| `Authorization: Bearer <token>`  | 登录后接口必填 | JWT 访问令牌 |

### 2.2 统一成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 2.3 统一失败响应

```json
{
  "code": 40001,
  "message": "参数错误：手机号格式不正确",
  "data": null
}
```

### 2.4 通用错误码

|   错误码 | 含义            | 典型场景               |
|------:|---------------|--------------------|
|   200 | 成功            | 请求处理成功             |
| 40001 | 参数错误          | 必填参数为空、格式不合法、金额超限  |
| 40101 | 未登录或 Token 无效 | 未携带 Token、Token 过期 |
| 40301 | 无权限           | 未完成学生认证、被封禁、访问他人订单 |
| 40401 | 资源不存在         | 任务、订单、用户不存在        |
| 40901 | 状态冲突          | 任务已被接单、订单状态不允许当前操作 |
| 42901 | 请求过于频繁        | 验证码发送频率过高          |
| 50001 | 系统内部错误        | 未预期异常              |

# 3. 用户认证与用户信息接口

## 3.1 发送短信验证码

| 项目     | 内容                |
|--------|-------------------|
| URL    | `/api/auth/sms`   |
| Method | `POST`            |
| 是否认证   | 否                 |
| 说明     | 向手机号发送验证码，用于登录/注册 |

### 请求参数

```json
{
  "phone": "13800000000"
}
```

| 参数    | 类型     | 必填 | 说明      |
|-------|--------|----|---------|
| phone | string | 是  | 11 位手机号 |

### 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "expireSeconds": 300
  }
}
```

### 失败响应示例

```json
{
  "code": 42901,
  "message": "验证码发送过于频繁，请稍后再试",
  "data": null
}
```

# 4. 任务管理接口

## 4.1 发布任务

| 项目     | 内容           |
|--------|--------------|
| URL    | `/api/tasks` |
| Method | `POST`       |
| 是否认证   | 是，且必须通过学生认证  |
| 说明     | 发布校园互助任务     |

### 请求参数

```json
{
  "type": "EXPRESS",
  "title": "帮取快递到鼓楼1舍",
  "description": "快递在南园驿站，取件码图片接单后可见。",
  "rewardAmount": 3.00,
  "rewardType": "CASH",
  "location": "南园驿站",
  "deadline": "2026-05-17T18:00:00",
  "attachments": [
    {
      "fileUrl": "https://cdn.example.com/task/pickup-code.jpg",
      "visibleToHelperOnly": true
    }
  ]
}
```

| 参数           | 类型       | 必填 | 说明                                                                                      |
|--------------|----------|----|-----------------------------------------------------------------------------------------|
| type         | string   | 是  | 任务类型：`EXPRESS`、`TUTORING`、`MATERIAL_SHARE`、`LOST_FOUND`、`SECOND_HAND`、`TEAM_UP`、`OTHER` |
| title        | string   | 是  | 任务标题，1-50 字                                                                             |
| description  | string   | 是  | 任务描述，1-500 字                                                                            |
| rewardAmount | decimal  | 是  | 报酬金额，非负数                                                                                |
| rewardType   | string   | 是  | `CASH` 或 `POINT`                                                                        |
| location     | string   | 是  | 任务地点                                                                                    |
| deadline     | datetime | 是  | 截止时间                                                                                    |
| attachments  | array    | 否  | 附件列表                                                                                    |

### 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "taskId": 30001,
    "status": "PUBLISHED"
  }
}
```

### 失败响应示例

```json
{
  "code": 40301,
  "message": "学生认证通过后才能发布任务",
  "data": null
}
```

## 4.2 浏览任务列表，含筛选排序

| 项目     | 内容                         |
|--------|----------------------------|
| URL    | `/api/tasks`               |
| Method | `GET`                      |
| 是否认证   | 可选；登录后可返回更多可见信息            |
| 说明     | 浏览任务列表，支持类型、报酬、关键词、状态、排序筛选 |

### Query 参数

| 参数        | 类型      | 必填 | 说明                                    |
|-----------|---------|----|---------------------------------------|
| type      | string  | 否  | 任务类型                                  |
| keyword   | string  | 否  | 标题/描述关键词                              |
| minReward | decimal | 否  | 最低报酬                                  |
| maxReward | decimal | 否  | 最高报酬                                  |
| status    | string  | 否  | 默认 `PUBLISHED`                        |
| sortBy    | string  | 否  | `createdAt`、`rewardAmount`、`deadline` |
| sortOrder | string  | 否  | `asc` 或 `desc`                        |
| page      | int     | 否  | 页码，从 1 开始                             |
| size      | int     | 否  | 每页数量，默认 10                            |

### 请求示例

```http
GET /api/tasks?type=EXPRESS&minReward=1&maxReward=10&sortBy=createdAt&sortOrder=desc&page=1&size=10
```

### 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 2,
    "page": 1,
    "size": 10,
    "items": [
      {
        "id": 30001,
        "type": "EXPRESS",
        "title": "帮取快递到鼓楼1舍",
        "rewardAmount": 3.00,
        "rewardType": "CASH",
        "location": "南园驿站",
        "deadline": "2026-05-17T18:00:00",
        "status": "PUBLISHED",
        "publisherNickname": "小罗"
      }
    ]
  }
}
```

## 9. API 审查结论

本 API 设计已覆盖作业要求的核心接口：用户注册/登录、发布需求、浏览需求列表、接单、查看订单详情、提交评价。同时补充了学生认证、完成凭证、确认完成、取消订单、托管支付和管理员审核接口，能够支撑 P0 业务闭环。

AI 生成 API 时容易出现以下问题，本版已修正：

| 问题      | 修正方式                                                        |
|---------|-------------------------------------------------------------|
| 接口命名不一致 | 统一使用 `/api/tasks`、`/api/orders`、`/api/reviews` 等 RESTful 命名 |
