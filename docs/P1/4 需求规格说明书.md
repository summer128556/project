
# 校园互助服务平台 需求规格说明书
**版本：V1.0**  
**日期：2026-04-12**  
**项目名称：Campus Helper**

---

## 1. 引言

### 1.1 目的
本文档定义校园互助服务平台的功能与非功能需求，确保开发、测试、运营三方对系统行为有一致理解。平台支持学生发布和接单快递代取、学习辅导、二手交易、组队匹配等互助任务。

### 1.2 范围
- **前端**：微信小程序（主要）+ 可选 APP
- **后端**：管理后台 Web
- **核心功能**：用户认证、任务发布/接单、订单管理、支付托管、信用评价、组队匹配
- **不包含**：校外商业广告、线下交付物流、真实货币借贷

### 1.3 定义
| 术语 | 说明 |
|------|------|
| 需求方 | 发起互助任务的学生 |
| 接单方 | 接受并完成任务的学生 |
| 信用分 | 基于订单完成率与评价的动态分数（0-100） |
| 托管支付 | 需求方预付，接单方完成后平台打款 |

### 1.4 参考文献
- IEEE Std 830-1998
- 前期用户访谈记录（2026.04）
- 竞品：某某校园、某某帮功能分析

## 2. 总体描述

### 2.1 产品视角
独立运行的校园服务系统，需集成：
- 微信小程序 SDK
- 微信支付
- 地图定位（腾讯地图 API）
- 学校统一认证（可选）

### 2.2 用户特征
| 角色 | 特征 |
|------|------|
| 普通学生 | 日均使用 5-15 分钟，对隐私敏感，习惯碎片化操作 |
| 管理员 | 校方或运营人员，处理纠纷、审核违规 |
| 系统运维 | 技术人员，监控日志与性能 |

### 2.3 约束
- 必须通过微信小程序内容审核及校方备案
- 学生证照片仅限校内存储，不得外传
- 单校并发用户 ≤ 3000（初期硬件限制）

### 2.4 假设
- 校内 4G/WiFi 网络稳定
- 学生愿意使用真实身份完成一次实名认证
- 大多数订单金额 ≤ 50 元（低风险）

## 3. 功能需求

### 3.1 用户认证模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-A01 | 用户使用手机号+验证码登录，首次登录需选择学校并上传学生证照片（后台人工审核通过后方可发布/接单） | P0 |
| F-A02 | 用户可编辑昵称、头像、宿舍楼地址 | P1 |
| F-A03 | 用户可查看信用分、完成单数、好评率 | P0 |

### 3.2 任务发布与浏览模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-B01 | 需求方可发布任务：类型（快递代取/学习辅导/二手/组队/其他）、标题、描述、报酬（元或积分）、截止时间、地点 | P0 |
| F-B02 | 快递代取任务必须上传取件码/快递单号照片（仅接单方可见） | P1 |
| F-B03 | 任务列表支持按类型、距离、报酬、发布时间筛选排序 | P0 |
| F-B04 | 接单方可查看任务详情并点击“接单”，同一任务只能被一人接单 | P0 |

### 3.3 订单管理模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-C01 | 订单状态流转：发布中 → 已接单 → 进行中 → 已完成 / 已取消 | P0 |
| F-C02 | 需求方或接单方可取消订单，取消方扣除 5 分信用分；30 天内取消 ≥3 次则限制接单 7 天 | P0 |
| F-C03 | 接单方完成任务后上传凭证（照片/文字），需求方确认完成；若 2 天内未确认，系统自动完成 | P0 |
| F-C04 | 订单完成后双方可互评（1-5 星）及文字评价 | P0 |

### 3.4 交易与支付模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-D01 | 支持现金（微信支付）与校园积分两种报酬方式 | P0 |
| F-D02 | 现金订单采用托管模式：需求方预付 → 接单方完成 → 平台打款（扣除 5% 手续费） | P0 |
| F-D03 | 积分仅用于发布需求或兑换礼品，不可提现 | P1 |

### 3.5 组队匹配模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-E01 | 用户可发布组队需求（自习/比赛/运动），其他用户申请加入，队长审批 | P1 |
| F-E02 | 组队成功后可生成临时群聊（24 小时后自动解散） | P2 |

### 3.6 安全与风控模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-F01 | 敏感词过滤（辱骂、广告、校外商业信息），违规内容自动隐藏 | P0 |
| F-F02 | 现金交易订单金额 ≥ 50 元时触发二次确认（人脸或短信验证） | P1 |
| F-F03 | 同一 IP 或设备短时间内频繁发布任务（>10 条/小时）触发人机验证 | P1 |

### 3.7 管理后台模块

| ID | 需求描述 | 优先级 |
|----|----------|--------|
| F-G01 | 管理员可查看所有订单、用户、纠纷列表，支持搜索和导出 | P0 |
| F-G02 | 管理员可手动调整订单状态、封禁用户、增减信用分 | P0 |
| F-G03 | 数据看板：日活、订单总量、各类型占比、投诉率 | P1 |

## 4. 非功能需求

### 4.1 性能

| ID | 需求描述 | 目标值 |
|----|----------|--------|
| NF-P01 | 列表页加载时间（4G 网络） | ≤ 1.5 秒 |
| NF-P02 | 系统支持同时在线用户数（单校） | ≥ 2000 人 |
| NF-P03 | 订单状态变更通知延迟 | ≤ 3 秒 |

### 4.2 安全

| ID | 需求描述 |
|----|----------|
| NF-S01 | 用户密码及交易信息使用 AES-256 加密存储 |
| NF-S02 | 所有接口防 SQL 注入、防重放攻击、HTTPS 传输 |
| NF-S03 | 学生证照片等敏感信息仅管理员可见，且操作留日志 |

### 4.3 可用性

| ID | 需求描述 | 目标值 |
|----|----------|--------|
| NF-A01 | 系统可用性（月度） | ≥ 99.5% |
| NF-A02 | 发布需求流程步骤数 | ≤ 3 个页面 |
| NF-A03 | 首次使用提供引导页（信用分规则、交易安全提示） | 必须 |

### 4.4 可维护性

| ID | 需求描述 |
|----|----------|
| NF-M01 | 后台提供管理员操作日志查询，保留 180 天 |
| NF-M02 | 核心业务模块（订单、支付、评价）提供 API 文档与注释 |
| NF-M03 | 错误日志自动上报至监控系统（如 Sentry） |

## 5. 需求追踪矩阵

将功能需求映射到对应的主要用例（Use Case），便于测试覆盖和变更影响分析。

| 需求ID | 对应用例 | 测试场景示例 |
|--------|----------|----------------|
| F-A01 | 用户注册登录 | 新用户上传学生证，审核通过后可发布任务 |
| F-A03 | 查看个人信用 | 用户完成 10 单无取消，信用分上升 |
| F-B01 | 发布任务 | 快递代取任务填写取件码，显示在列表中 |
| F-B04 | 接单任务 | 两人同时点击接单，只有一人成功 |
| F-C01 | 订单流转 | 从发布中 → 已接单 → 进行中 → 已完成 |
| F-C02 | 取消订单 | 用户取消第 3 次时收到“限制 7 天”提示 |
| F-C03 | 自动完成 | 需求方 2 天不确认，系统自动完成并打款 |
| F-D02 | 托管支付 | 需求方支付 10 元，接单方完成后收到 9.5 元 |
| F-E01 | 组队匹配 | 队长审批加入申请，成员出现在队伍中 |
| F-F01 | 敏感词过滤 | 发布含“代考”内容自动拦截并提示 |
| F-G01 | 后台订单管理 | 管理员按状态筛选全部订单 |
